# Stage 2 hardware OOM matrix

The [fixture](../../../tests/embedded_gc_stage2_oom_matrix_device.bmx) keeps a registered worker polling while the owner fills the 64 KiB heap with sixty or fewer rooted 1 KiB Objects. It clears alternating roots and collects, leaving more than 8 KiB reusable in separated holes, each smaller than a 4 KiB request. A 4 KiB Object, a 4 KiB Array and a 4 KiB String must each throw locally despite the aggregate free space. It also checks that a raw arena request larger than the arena returns null and increments the failure count. After clearing all remaining roots, collecting and coalescing, the same three managed requests must succeed; final collection restores all live counts and valid heap metadata.

On 2026-11-04, both Pico 2 and ESP32-S3 release images passed: `GC_STAGE2_OOM_MATRIX,format=1,fragmented=pass,object=pass,array=pass,string=pass,arena=pass,recovery=pass,done=1`. The separate [worker lifecycle soak](multicore_stage2_soak_hardware.md) exercises all three OOM paths on the worker over one million job cycles. The [concurrent stress fixture](multicore_stage2_stress_hardware.md) exercises the same paths on both tasks during allocation and atomic publication.
